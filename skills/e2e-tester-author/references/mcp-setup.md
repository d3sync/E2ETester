# Local agent setup

Use the single-file Windows distribution's `mcp/E2ETester.Mcp.exe`. Run the skill's `scripts/Setup-Agent.ps1 -McpExecutable <absolute-exe> -BaseUrl <approved-api-root> -ConfigureCodex`. Without ConfigureCodex it writes a generic MCP client configuration only. The script installs this skill, copies the binary to a stable per-user Agent/bin directory, creates a separate agent workspace, and registers `e2e-tester` with the Codex CLI. Existing host permissions/configuration are preserved. Restart the agent to discover newly installed capabilities.

The default API root is a reserved example.test placeholder; supply your own approved server. Do not broaden the allowlist beyond the requested API. HTTP/authoring are enabled for that root; saved SQL and native interactive login are disabled. Tokens are read only from `E2ETESTER_CLOUD_TOKEN` in the server process environment. Set that locally before starting the agent. Never put tokens into command-line arguments, chat, skill files or client JSON. Microsoft MFA remains an interactive user action. Swagger's persisted desktop cookies are not automatically available to MCP; without an authenticated token, generate/validate packages and let the user execute them in the desktop.

For another MCP client use the generated `mcp-client.json`, adapting only its client-specific wrapper. For Codex, the setup uses the official `codex mcp add name -- executable --config file` interface and leaves other servers unchanged. Reference: https://developers.openai.com/codex/mcp

After setup, inspect `capabilities`, then `validate_package`. To run an authorized suite: start_run, prepare_case, execute_prepared, poll get_operation, inspect get_attempt/get_run. Complete the Swagger token-availability case, then remote-IP validation, then business cases. Missing credentials or failed validation are a stopping condition, not permission to bypass setup. Reuse execution IDs after uncertain delivery. Finish the run and save get_report JSON; reports retain every attempt. No MCP tool fetches secrets or runs arbitrary SQL; saved queries require exact host approvals.
